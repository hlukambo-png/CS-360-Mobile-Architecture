# CS 360 Mobile Architecture and Programming

## StockKeeper Inventory Management Application

### Project Overview

StockKeeper is an Android mobile application developed for CS 360 at Southern New Hampshire University. The application allows users to manage inventory, track stock levels, and receive notifications about inventory shortages. It was developed using Android Studio and demonstrates mobile application development, user-centered design, data management, and application testing.

### 1. Briefly summarize the requirements and goals of the app you developed. What user needs was this app designed to address?

The goal of my StockKeeper application was to provide users with a simple and reliable way to manage their inventory using a mobile device. The application was designed to address the need for organized inventory tracking, allowing users to add, view, and delete inventory items while monitoring stock availability. Important requirements included user authentication, inventory management, persistent data storage, and notifications for out-of-stock items. I wanted to develop an application that would be practical, accessible, and easy to navigate.

### 2. What screens and features were necessary to support user needs and produce a user-centered UI for the app? How did your UI designs keep users in mind? Why were your designs successful?

My application required a login screen, an inventory management screen, controls for adding and deleting items, and an SMS notification permission feature. I designed the interface with simplicity and usability in mind by organizing the features logically and making important functions easy to access. Input validation was incorporated to prevent incorrect login information from being accepted. The inventory interface allows users to manage items without navigating through unnecessary screens. I believe the design was successful because I was able to use the application in the Android emulator and complete its primary inventory management operations.

### 3. How did you approach the process of coding your app? What techniques or strategies did you use? How could those techniques or strategies be applied in the future?

I approached development by dividing the application into smaller components and implementing the necessary features incrementally. I started with the user interface and then worked on login validation, inventory operations, data storage, and notification functionality. I used Android Studio's development tools and Gradle build system to identify and resolve implementation problems. Testing individual features before moving to others helped me identify issues more efficiently. In future projects, I plan to continue using incremental development, modular code organization, and frequent testing to improve maintainability and reduce errors.

### 4. How did you test to ensure your code was functional? Why is this process important, and what did it reveal?

I tested StockKeeper using the Android Studio emulator. I verified that the application launched, incorrect login credentials were rejected, inventory items could be added and deleted, and saved inventory information was retained. I also tested the out-of-stock alert functionality and the application's SMS permission and notification workflow. These tests helped demonstrate that the main features worked as intended while identifying areas that required additional attention. Testing is important because it helps developers find defects, verify requirements, and improve the overall user experience before releasing an application.

### 5. Consider the full app design and development process from initial planning to finalization. Where did you have to innovate to overcome a challenge?

One of the biggest challenges I encountered was getting the Android emulator to run the application consistently. During development, the emulator occasionally became unresponsive, displayed a black screen, or experienced startup problems. I worked through these challenges by troubleshooting the emulator, checking the Gradle build process, and repeatedly testing the application until it launched successfully. Another challenge involved connecting the user interface to working inventory management functionality. By breaking the problems into smaller tasks and testing each component, I was able to complete the application. This experience strengthened my troubleshooting skills and taught me the importance of persistence in software development.

### 6. In what specific component of your mobile app were you particularly successful in demonstrating your knowledge, skills, and experience?

I was particularly successful in implementing the inventory management functionality. The ability to add, delete, and save inventory items demonstrated my understanding of mobile user interface development, application logic, and data management. I was also successful in implementing login validation and testing the out-of-stock notification feature. Seeing these components function in the Android emulator gave me confidence in my ability to design and develop a working mobile application. Overall, StockKeeper represents meaningful progress in my software development skills and provides a project I can showcase in my professional portfolio.
